# Grill with Docs UI

组合 sibling `grill-with-ui` 的远程问卷与 `grill-with-docs` 的领域文档维护。访谈、真实答复和继续执行都归属于来源会话。

## 加载依赖

- [grill-with-ui](../grill-with-ui/SKILL.md)：使用前 GitHub 更新检查、本地服务器变量、凭据、请求创建、默认浏览器、来源身份、前台等待、消费确认和恢复。使用它的 `scripts/handover.mjs`，不复制或启动旧版服务器。
- [grill-with-docs](../grill-with-docs/SKILL.md)：维护词汇表和符合条件的 ADR。
- [grilling](../grilling/SKILL.md)：设计探索与待解决问题。已确认的决定及实施授权继续有效，不重复设置确认关卡。
- [domain-modeling](../domain-modeling/SKILL.md)：文档归属、词汇表及 ADR 标准；写相应文档前读取它的格式说明。

相对路径以本 Skill 为基准；命令中的 `$SKILL` 指 `grill-with-ui` 的目录。缺依赖时先查找已安装位置，如实说明不可用步骤。只编辑、审查本 Skill 时不发起访谈；用户要求聊天文字版时直接遵从。

## 文档归属

根据任务和项目规则确定目标项目，读取已有 `CONTEXT-MAP.md`、相关 `CONTEXT.md` 与 ADR。归属不明时先把拟议术语留在聊天，向用户澄清；不把无项目会话目录当作目标项目。只有已经确定的内容才写文件，保留现有无关修改。

## 每轮访谈

1. 先查清仓库里可以发现的事实，在普通聊天简要列出已确认理解、必要背景和待决问题。
2. 每轮通常问 2–4 个独立且影响结果的问题；只有一个必要问题时问一个。给出简明选项、推荐及取舍，不默认制作可视化。依赖前题的问题等真实回答后再提出。
3. 按新版 `grill-with-ui` 在同一服务器发起请求并用系统默认浏览器打开。普通聊天保留相同问题；核实来源会话与 handle。手机可以在相同请求里回答。
4. 本组合适用用户级 AGENTS.md 的远程交接工具等待例外：来源 Agent 在当前回合前台分段 `wait`，每段最长 30 秒。不得创建后台等待、监控、其他会话或内置问答控件。超时继续同一请求；中断保留请求 ID、handle 和恢复位置。
5. 只根据匹配来源与请求的真实事件继续。先写回答案和文档，再按远程 Skill 用 `ack` 确认连续序号；恢复时核对已有状态，避免重复追加讨论或 ADR。默认值、预选、打开网页、发送通知和等待超时都不是答复。部分答复不批准尚未回答的问题。

## 维护文档

术语确定后及时更新其所属 `CONTEXT.md`，遵循领域词汇表格式。保持它是纯领域词汇表，不放实施计划、访谈记录、UI 状态或任务清单。新答案与已有代码或术语冲突时，先说明差异，再根据确认结果更新。

只有同时满足以下条件才提出 ADR：撤回成本明显、未来读者缺少背景会困惑、存在真实备选和取舍。遵循项目编号及状态约定；未确认的建议不写成接受，避免每题或每轮生成 ADR。

需要下一轮时在同一远程请求内追加新 ID 的问题，继续等待。没有实质待决事项时概述最终方案、文档变化和实际验证限制；尚缺实施授权才请求确认。已有明确“开始执行”或同等授权时直接继续，不重复确认。完成后用远程客户端结束请求。
